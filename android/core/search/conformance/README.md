# Search conformance: Kotlin against the Python reference

The Kotlin engine in `:core:search` must give the same answers as `packbuilder/search/query.py`
and `packbuilder/addresses/addrlib`. This folder holds the inputs and the scripts; the reference
answers and the findings go to `data/search-conformance/` (not in git: they contain pack data,
and the address cases are real addresses).

| File | What it is |
|---|---|
| `search_queries.json` | 1,089 queries: the three test sets of `packbuilder/search/tests` (355 tuned (10 of them the `natural` cases of next-round item 14), 99 held-out, 49 review, with their expectations) and 586 extra ones (prefixes of 1-4 letters, typing letter by letter, brand names with punctuation, numbers, addresses, vocabulary words, hostile strings, bad and far-away positions). Generated by `make_queries.py` (seed 20261115) and committed. |
| `make_queries.py` | regenerates `search_queries.json` from the test sets and the search database |
| `make_reference.py` | runs the Python engines and writes the reference answers, the e2e hold-out copy of the address file, and the normaliser dumps |
| `compare.py` | independent check (Python only) of the Kotlin answers that the Kotlin test dumps |
| `negative_control.py` | a reference with nine deliberate changes; the Kotlin tests must report all nine |
| `sql_probe.py` | Python twin of `SqlTimingProbe.kt` (SQLite time versus engine time) |
| `bench_tables.py` | Markdown tables from the JVM, Python and device benchmark outputs |
| `interleaved_bench.py` | Kotlin JVM benchmark and Python `measure.py` back to back, alternating, several rounds, CPU load read around each run; ranges and per-round ratios in `data/search-conformance/interleaved/summary.json` |

## Run

From the repository root (Windows paths as on the build PC; any Python 3.12 works, the scripts
use the standard library and the code in `packbuilder/`):

```
python -I android/core/search/conformance/make_reference.py \
    --search-db <data>/search/pa-search.sqlite \
    --addresses-db <data>/addresses/pa-addresses-slim.sqlite \
    --e2e-cases <data>/addresses/reports/e2e_cases.csv
cd android
BEAMLINE_TESTS_STRICT=1 ./gradlew :core:search:test   # conformance, pass rates, normaliser, unit tests
cd ..
python android/core/search/conformance/compare.py
python android/core/search/conformance/negative_control.py      # 9 planted differences
python android/core/search/conformance/negative_control.py --only title,score,distance,label --dst data/search-conformance-negative-fields
python android/core/search/conformance/negative_control.py --only stale --dst data/search-conformance-negative-stale
cd android
BEAMLINE_CONFORMANCE_DIR=<repo>/data/search-conformance-negative ./gradlew :core:search:test \
    --tests '*SearchConformanceTest*' --tests '*AddressConformanceTest.sameAnswersAsAddrlib*'   # must fail, 9 findings
```

Run the same Gradle command with `...-negative-fields` (must fail: 3 field and 1 label difference,
ids and verdicts equal) and `...-negative-stale` (must fail: "packbuilder/search/query.py changed
since the reference was made").

The tests read the database paths from `android/local.properties` (`beamline.searchDb`,
`beamline.addressesDb`) and skip when they are not set, or fail in strict mode
(`BEAMLINE_TESTS_STRICT=1`).

Freshness: `make_reference.py` writes a fingerprint into `reference-search.json`,
`reference-addresses.json` and `norm-fingerprint.json`: the SHA-256 of the input files and of every
reference source (each `packbuilder` module the Python engines import, their JSON rule files,
`points.json`, `search_queries.json`; text hashed with LF line endings). The Kotlin tests recompute
it and fail when a source changed or the configured packs are other files, so a stale reference
cannot pass. Every difference fails a test: ids, fields, parse labels, flags and verdicts for
search; parse fields and results for addresses.

What is compared:

- search: for every query, the top-10 result ids in order, then every field of every result
  (title, subtitle, category label and id, kind, lat/lon, distance, brand, score to 4 decimals,
  how, tier, house number fields), the parse labels, the out-of-coverage and position flags, and
  for the test sets the top-1 / top-5 / data-gap verdict of `run_tests.py`'s checker (ported to
  Kotlin in `Checker.kt`), so the pass rates are compared per case;
- addresses: for the addresses track's 435 end-to-end variants and 90 extra strings, every parsed
  field and every field of the top-5 lookup answers, on the pack file and on a copy with the target
  addresses removed (positions within 1e-9 degrees, everything else exactly);
- normalisers: the search key of every distinct entry name of the search pack (227,152), and the
  street key, core key and key variants of every distinct street spelling (170,448), the place key
  of every city, municipality and place name (3,449) and the house number of every distinct
  house-number spelling (24,774) of the address pack.
